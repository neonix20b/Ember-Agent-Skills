# Static userland builds

When to build the EmberBSD userland fully static, the exact flag set that works,
and the pitfalls that cost a full day of build cycles the first time. Verified on
2026-10-10/11 by cross-building, installing and running the complete static
reduced base on a physical Raspberry Pi 5 (`ember-rpi5-01`), source revision
`383e2a9dc502eeddab2abb6a628580737cbba0b3`.

## When static is the right answer — and when it is not

Static linking helps fixed system images, recovery media, and self-contained
appliances: nothing can desynchronize the dynamic loader, libc, and libraries,
and the image works without `ld.elf_so`. It does **not** speed up boot:
measured on identical hardware, the rc phase reached completion at +8 s on the
static base versus +6 s on the dynamic one, and the archive grew from 36 MiB to
144 MiB. Do not promise a faster start; state the simplicity and robustness gain.

## The flag set that works

Extend the reduced-base profile from the OS `ember/boot/aarch64-base-update.md`
guide with:

```text
MKPIC=no MKPICINSTALL=no MKPIE=no LDSTATIC=-static MKZFS=no MKDTRACE=no
```

Why each flag matters:

| Flag | Reason |
|---|---|
| `LDSTATIC=-static` | The single missing piece: it is how the tree itself links static programs (`distrib/common/Makefile.crunch`). Without it the gcc driver still adds `-Wl,-dynamic` and requires `-lgcc_s`/`crtendS.o`, which a static tree never builds. |
| `MKPIE=no` | PIE executables need `crtbeginS.o`/`crtendS.o`; a static profile links non-PIE. |
| `MKZFS=no`, `MKDTRACE=no` | The cddl tools do not link statically today: circular `libzfs`/`libzfs_core` dependencies and `rd_loadobj_iter` from `librtld_db`. Excluding them is legitimate for appliance images; keep `MKCTF` untouched — kernel CTF is independent. |
| `MKPIC=no MKPICINSTALL=no` | No shared objects are built or installed; set lists filter correctly and the strict `checkflist` passes. |

Keep `INSTALLSETS=base` and the rest of the reduced profile unchanged. The
`base` set then contains zero `.so` files and no `ld.elf_so`; `file(1)` on
`/bin/sh` reports `statically linked`.

## Tools rule: never build tools under the reduced flag set

The gcc target libraries in the world build (`libobjc`, `crtstuff`, `libgcc`,
`libstdc++-v3`) include headers generated by the full gcc tool build
(`tools/gcc/build/gcc/...`). If `build.sh tools` runs with `MKGCCCMDS=no`, it
produces a driver without those generated files, and every gcc library in the
world fails on `tm.h` → missing `insn-constants.h`. Build tools once without
the reduced flags (the kernel wrapper path does this), then reuse that TOOLDIR
for the static tree with its own `-O` objdir:

```sh
build.sh ... -O "$STATIC_OUT/obj" -T "$COMPLETE_TOOLDIR" ... makewrapper
```

Skip the `tools` target entirely on reuse; regenerate only the `makewrapper`.
A stale reference to the static tree's own TOOLDIR is fixed with a symlink
`$STATIC_OUT/tools -> $COMPLETE_TOOLDIR`.

## From-scratch races: the catalog

A clean parallel world build currently trips over local-generation races:
`nbmkdep` runs before the makefile rule that generates a header or data file in
the same directory. Each stop is recoverable — rerun after generating or
copying the artifact — but knowing the list saves hours:

| Component | Missing artifact |
|---|---|
| `external/bsd/am-utils/lib/libamu` | `config_local.h` |
| `external/gpl3/gcc/lib/libobjc`, `crtstuff` | `optionlist`, `options.h`, `tconfig.h`, `runtime-info.h`, `insn-constants.h`, `insn-flags.h`, `gthr-default.h` |
| `external/gpl3/gcc/lib/libstdc++-v3` | `bits/largefile-config.h` and friends |
| `crypto/external/apache2/openssl` | `buildinf.h` |
| `external/bsd/fetch/lib` | `ftperr.h`, `httperr.h` |
| `usr.sbin/sysinst` | `sysinstmsgs.fmtcnt` |
| `games/boggle` | `dictionary` |
| `sys/external/bsd/acpica` (iasl) | `dtparser.y.h` |
| `lib/libpam` | `openpam_static.o` |
| `rescue` | `liboverride.o` |
| `sys/dtb` | `*.dtb` (built by the kernel flow, not the base) |
| `sys/stand/efiboot` | does not link under a global `-static` (`PHDR segment not covered by LOAD segment`) |

Two safe sources for a missing artifact: pre-generate it with the make wrapper
(`nbmake-evbarm -C <dir> <target>`) before the world run, or copy it from the
objdir of a complete build of the same sources — generated files are
deterministic. For the EFI bootloader, reuse the complete build's
`bootaa64.efi(.so)` artifacts. Also expect sporadic host `cc1` SIGSEGV/SIGBUS
crashes on cross hosts under `-j6`+; a plain rerun of the same target passes —
abortions leave partial targets, so resume the world rather than rebuilding.

Keep such resume logic in a script (generate-or-copy the known artifacts, then
rerun `distribution` and `sets`); a hand-typed sequence will forget a step.

## Install and verify on the board

1. Chroot-check the candidate first. A static tree needs no `ld.elf_so`; for
   script conveniences create `/dev/null` as `mknod c 0 2` and remove it after.
2. Install with `tar -xpf` over the running system, restore the board's radio
   firmware overlay and verify its hashes — the base set does not carry them.
3. **Restart the critical services before rebooting** (`sshd`, `wpa_supplicant`,
   `dhcpcd`) and open a new SSH session: this proves the static binaries work
   while a recovery path still exists.
4. After reboot, confirm the kernel revision is untouched, run the quick
   functional checks (memfd, FP state), and check `file /bin/sh`.
5. Keep the previous dynamic `base.tar.xz` on the board for a one-command
   rollback; `tar` does not delete old `.so` files, so remove them explicitly
   when the static profile must be clean.

Known boundary: statically linked `wpa_supplicant`, `sshd` (public-key login)
and `dhcpcd` all work on the verified board, including SAE/WPA3 association.

## Reporting

Record the flag set, the source revision, hashes of the sets and key binaries,
the checks actually run, and the honest boot-time comparison. Point future
fixes at the race catalog above — each entry is a candidate for a proper
dependency fix in the tree so the workaround can be retired.
